# Decision preparation — v1

L5 decision-preparation.mjs owns pure preparation through existing project/decision_preview. Four tools now compose eleven operations. No new endpoint or mutation is added. Existing decision_update remains the final authenticated revisioned, conserving save.

Input: revision, whole decisions document, edits:[{transaction_id,fields}]; at most500 edits. Field allowlist: purpose/group/category/travel_purpose/insurance_type/evidence/inflow_role. Values are strings, max149 characters except evidence20000. Omitted fields preserve existing values; deletion/null is unsupported. Conflicting duplicate field edits reject; compatible edits merge. Unknown IDs and protected/economic fields reject. Travel/insurance/inflow options are the executable decisionChoiceOptions; only explicitly edited Unresolved inflow normalizes to empty. Unedited legacy values remain unchanged.

Output: revision, detached prepared_decisions, effective_record_states from the same dashboardRows projection (selected snapshot window), including effective_scope and scope_reason from shared scopeAttribution, suggestions:[transaction_id,field,current_value,proposed_value,reason], dependent_suggestions_applied=false. Explicit purpose and category win. Work travel can suggest Business; insurance type can suggest a more specific category. Suggestions never enter prepared_decisions automatically. Preview does not create accepted reviews, change facts/payment status or advance revision. Discovery publishes input and output schemas. Whole-document validation/economic conservation is reused.

The editor submits the visibly selected purpose explicitly on Save, preventing unreviewed travel inference from overriding that choice. Other fields are submitted only when changed from opening values, retaining unsupported existing select values visibly. A protocol preview omitting purpose reports existing inference in effective_record_states rather than falsely describing unchanged effective purpose. Preview responses apply only if editor identity, loaded revision, all field values and sibling draft are unchanged. Optional suggestion buttons change a choice and require another preview. A conflicting preview is displayed before Save these choices. A save acknowledgement cannot close a newer editor or newer unsaved choices. Failed saves retain the draft.

Scoped tests include explicit Household+Work purpose, insurance category preservation, accepted-review history, unknown/protected/stale/conflicting edits, detached output, actual HTTP/stdio parity under a held writer lock, actual controller changed-field submission and save acknowledgement races. Deployed/client/formal rendered acceptance remains separate.

Scope membership remains separate from purpose. Saved commitment assignment, Business purpose, work receipts and Mixed business inflow precede the Home default under existing rules. The same scopeAttribution function drives scopeRows and the preview, without changing historical routing. Household purpose with a Mixed inflow role stays Work; Household Work-travel without those other signals stays Home. The UI reviews conflicting-purpose/scope placement before saving rather than inferring Home from purpose.

## Commitment moves and acknowledgement baseline

Optional `commitment_moves` accepts at most500 intents: name (nonempty, max300), to_scope (home/work), seed_essential (boolean), seed_monthly_amount (finite nonnegative number). The same L5 prepareCommitmentMoves function serves protocol preview and the move button. Existing destination essential/amount fields are preserved by own-property presence, including false/zero and null amount (explicit fallback/unset). Only absent fields are seeded from current choices. Unrelated billing, targets and source scope fields stay intact. Exact duplicate moves collapse; conflicting duplicates reject. `planning_changes` describes names/scopes and preserved versus seeded fields. Final validateDecisions/conservation remains mandatory; preview never persists.

The editor compares choices with its last confirmed submitted form baseline, initially the opening form. Confirmed earlier saves update that baseline even when newer sibling drafts remain. Failed saves do not. Reload captures raw editor fields and generation across the read, including explicit-discard requests; later raw edits cancel the response. A successful applied reload closes its obsolete editor, while dirty normal reload is refused. These guards preserve drafts without turning previews into writes.
