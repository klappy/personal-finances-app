# Remote MCP authentication preparation — October 7, 2026

Chosen candidate: Cloudflare Access Managed OAuth on the existing self-hosted application. Cloudflare's [Managed OAuth documentation](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/managed-oauth/) says RFC8707-compatible clients authenticate through the existing Access policies; the origin continues to validate Cf-Access-Jwt-Assertion. This preserves per-user authorization without introducing a service principal or storing client credentials in Git.

Actual state: dev Access app is self_hosted; oauth_configuration is absent. Managed OAuth is not enabled. Worker validates RS256 issuer/audience/time/hostname and the private allowed-email list. Dev v0.5.25 is deployed through Git build9a712599-e5d7-4c1e-8404-02a9b8b4cd41 at commit a9a2d90a7b51fac52e962dd355e4e04a63c911a3. Unauthenticated requests redirect to Access; authenticated browser and remote-client authorization remain unproven. Browser clients blocked the dev hostname after login.

API specification inspected: Access application update accepts oauth_configuration.enabled; dynamic_client_registration.enabled, allowed_uris, allow_any_on_localhost and allow_any_on_loopback; grant.access_token_lifetime and grant.session_duration. Client redirect URIs must be established before enabling registration. No broad wildcard or undocumented callback is assumed. OAuth sessions should preserve the owner's one-month login request; short-lived access tokens may refresh within that session.

Staging sequence: the reviewed dev build and private two-user runtime allowlist are configured; next prove origin authentication and protected assets, then enable Managed OAuth on dev without changing recipient policies. Configure only the actual clients' documented registration callbacks, test unauthorized denial and both authorized discovery/tools/query flows, and compare core/HTTP/MCP payloads against identical revisions. Before changing Access, GET the complete existing application configuration, preserve every existing setting and policy reference, then PUT the full updated configuration. A partial PUT can overwrite existing settings. Re-read the application and policies and preserve before/after evidence. Production OAuth changes wait for the verified staging result.

Limits: Cloudflare resolves its opaque OAuth token into the origin Access JWT; the Worker must not attempt to parse an opaque bearer token as identity or bypass its audience/allowlist checks. No Linked App Token policy is required for this co-located core: the MCP face dispatches directly rather than proxying a second downstream service. Browser login alone is not proof of an agent client's OAuth flow.
